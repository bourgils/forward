# 🤝 Contributing to Forward

Thank you for your interest in contributing to Forward! This document provides guidelines for contributing to the project.

## 📝 Issues

### Creating an Issue

1. **First check** if a similar issue already exists
2. **Use the appropriate template**:
   - 🐛 Bug Report
   - ✨ Feature Request
   - 📚 Documentation
   - ❓ Question

### Writing an Issue

- **Title**: Be concise and descriptive
- **Description**: Include:
  - Expected behavior
  - Current behavior
  - Steps to reproduce
  - Forward version
  - OS and version
  - Screenshot if relevant

## 🔄 Pull Requests

### Process

1. **Fork** the project
2. **Create a branch**: `git checkout -b feature/my-feature`
3. **Commit** your changes: `git commit -m 'feat: add amazing feature'`
4. **Push** to your fork: `git push origin feature/my-feature`
5. **Open a Pull Request**

### Code Standards

- **Formatting**: Follow the existing code style
- **Tests**: Add tests for new features
- **Documentation**: Update documentation if needed
- **Commit messages**: Use conventional format:
  - `feat:` for new features
  - `fix:` for bug fixes
  - `docs:` for documentation
  - `style:` for formatting
  - `refactor:` for refactoring
  - `test:` for tests
  - `chore:` for maintenance

### Code Review

- PRs will be reviewed by maintainers
- Respond to comments and suggestions
- Keep PR up to date with main branch

## 🎯 Best Practices

- **Communication**: Be respectful and constructive
- **Tests**: Ensure all tests pass
- **Documentation**: Update README and documentation if needed
- **Scope**: Keep PRs focused on a single change
